# gametools

A full suite of tools designed to provide:
- [x] Loading Screens
- [x] Start menus
- [x] Save / load system
- [x] Options menus
  - [x] Display settings
  - [x] Sound settings
  - [ ] Gameplay settings (storage only — apply logic is game-specific)
  - [ ] Accessibility settings (storage only — apply logic is game-specific)
- [x] Mod support (PCK loading, sidecar manifests, enable/disable, Steam Workshop)

---

## Installation

1. Copy the `addons/netpunk.gametools/` folder into your project's `addons/` directory.
2. Open **Project → Project Settings → Plugins** and enable **Netpunk.GameTools**.
3. The plugin registers four autoloads automatically — `SaveManager`, `ModManager`, `OptionsManager`, and `LoadingManager`. Confirm they appear in **Project → Project Settings → Autoloads**.

---

## Plugin Configuration

When the plugin is enabled a **GameTools** dock appears in the editor (bottom-left by default). It exposes settings stored in `project.godot` via ProjectSettings and read by the autoloads at runtime.

**Save System**

| Setting | Default | Description |
|---|---|---|
| Version file | `res://version.json` | Path to the CI-generated version JSON. Use **…** to browse. |
| Max slots | `3` | Number of save slots (1–99). |
| Use encryption | `false` | Encrypt save files with AES. |
| Encryption key | *(empty)* | Passphrase — only configure here for development; set at runtime in production. |

**Options**

| Setting | Default | Description |
|---|---|---|
| Gameplay setting keys | *(empty)* | Keys in the `gameplay` category — stored, not auto-applied. |
| Accessibility setting keys | *(empty)* | Keys in the `accessibility` category — stored, not auto-applied. |

**Mods**

| Setting | Default | Description |
|---|---|---|
| Mods path | `user://mods/` | Directory scanned for `.pck` mods at startup. See [Mod Support](#mod-support). |

**Loading Screen**

| Setting | Default | Description |
|---|---|---|
| Meta key | `"chapter"` | Save metadata key used to look up a background image. |
| Default image | *(empty)* | Fallback texture path when no metadata key matches or no save exists. |
| Background mappings | *(empty)* | List of meta value → image path pairs. Add rows with **+ Add Mapping**. |
| Transition type | `none` | `none`, `fade`, `slide`, or `shader`. |
| Duration in | `0.4` | Seconds for the transition-in animation (hidden when type is `none`). |
| Duration out | `0.4` | Seconds for the transition-out animation (hidden when type is `none`). |
| Direction | `left` | Slide origin edge — `left`, `right`, `up`, or `down` (Slide only). |
| Shader | *(empty)* | Path to a `.gdshader` file (Shader only). See [Custom transitions](#custom-transitions). |

Settings are written to disk immediately on change. You can also inspect or override them directly in **Project → Project Settings → gametools/**.

## Getting Started

The three autoloads work together. A typical game flow looks like:

```
Game opens
  └─ Show start_menu.tscn
       ├─ New Game  →  LoadingManager.go_to("res://scenes/game.tscn")
       ├─ Continue  →  SaveManager.load_slot(n)  →  LoadingManager.go_to(...)
       └─ Load Game →  show your slot-picker UI  →  SaveManager.load_slot(n)  →  LoadingManager.go_to(...)

In-game
  ├─ Save progress      →  SaveManager.save_slot(...)
  └─ Options menu open  →  OptionsManager.begin_editing()
                           OptionsManager.commit() / cancel()
```

Autoload dependency order (registered automatically in this order):

```
SaveManager          ← base; no dependencies
ModManager           ← reads enabled states from SaveManager; mounts PCKs before other systems run
OptionsManager       ← loads/saves via SaveManager
LoadingManager       ← reads SaveManager metadata for background image selection
```

## Save / Load System

The `SaveManager` autoload is registered automatically when the plugin is enabled.

### Configuration

Set these on `SaveManager` before your first save/load call (e.g. in your game's `_ready`):

```gdscript
SaveManager.max_slots = 5          # default: 3
SaveManager.use_encryption = true  # default: false
SaveManager.encryption_key = "s3cr3t"
SaveManager.version_file_path = "res://version.json"  # default
```

For production builds, set the encryption key at runtime rather than committing it to `project.godot`:

```gdscript
func _ready():
    SaveManager.encryption_key = OS.get_environment("SAVE_KEY")
    SaveManager.use_encryption = true
```

### Version stamping & compatibility

`SaveManager` reads `res://version.json`, which is generated by your CI pipeline:

```json
{
  "version": "pre-alpha: v0.2.4"
}
```

The `version` field is stamped as `game_version` into every new save's meta automatically. The semver is extracted from the string (prefix like `"pre-alpha: v"` is ignored), and **any change in major version** is treated as a breaking change — saves from a different major version get `possibly_incompatible: true` added to their meta when loaded.

```gdscript
var save := SaveManager.load_slot(0)
if save.meta.get("possibly_incompatible", false):
    show_warning("This save was created with an incompatible version.")
```

The flag is non-destructive — it only exists in the returned dictionary, never written to disk. If `version.json` is missing or a save has no `game_version` field, the check is silently skipped.

### Settings (global, one file)

```gdscript
# Save
SaveManager.save_settings({"master_volume": 0.8, "fullscreen": true})

# Load
var settings := SaveManager.load_settings()
```

### Save Slots

```gdscript
# Save — pass custom meta fields your UI needs (playtime, character level, etc.)
SaveManager.save_slot(0, {
    "player_hp": 100,
    "position": Vector2(32, 64),
}, {
    "playtime_seconds": 3600,
    "character_level": 5,
    "map_completion": 0.42,
})

# Load a slot → {meta: {...}, data: {...}}
var save := SaveManager.load_slot(0)
var hp: int = save.data.player_hp

# List all slots (for a save-select screen)
var slots := SaveManager.list_slots()
# [{slot:0, exists:true, meta:{...}}, {slot:1, exists:false, meta:{}}, ...]

# Housekeeping
SaveManager.slot_exists(0)         # → bool
SaveManager.get_slot_meta(0)       # → Dictionary (cheap, skips game data)
SaveManager.delete_slot(0)         # → bool
SaveManager.get_last_used_slot()   # → int (-1 if none)
SaveManager.get_last_slot_meta()   # → Dictionary
```

### File layout on disk

```
user://
  settings.json
  slots/
    slot_0/
      meta.json   ← slot, last_played, game_version, + your custom fields
      data.json   ← game data
    slot_1/
      ...
```

## Options Menu

The `OptionsManager` autoload applies display and audio settings to the engine immediately and persists them via `SaveManager`. You build your own themed UI; the plugin provides the logic and unstyled widget components.

### Edit session

```gdscript
# When player opens the options menu:
OptionsManager.begin_editing()   # snapshots state for cancel/revert

# When player clicks Apply / OK:
OptionsManager.commit()          # saves to disk, emits settings_committed

# When player clicks Cancel:
OptionsManager.cancel()          # reverts to snapshot, reapplies previous values
```

### Reading / writing settings directly

```gdscript
OptionsManager.set_setting("display", "window_mode", DisplayServer.WINDOW_MODE_FULLSCREEN)
OptionsManager.get_setting("display", "window_mode", DisplayServer.WINDOW_MODE_WINDOWED)

OptionsManager.set_setting("display", "resolution", [1920, 1080])
OptionsManager.set_setting("display", "vsync", DisplayServer.VSYNC_ENABLED)
OptionsManager.set_setting("display", "fps_limit", 60)  # 0 = unlimited

# Audio bus by name (any bus in your AudioServer layout):
OptionsManager.set_setting("audio", "Master", 0.8)  # 0.0–1.0 linear
OptionsManager.set_setting("audio", "Music", 0.5)

# Gameplay / accessibility — stored but not auto-applied; listen to the signal:
OptionsManager.set_setting("gameplay", "difficulty", 2)
OptionsManager.setting_changed.connect(func(cat, key, val):
    if cat == "gameplay": apply_my_gameplay_setting(key, val))
```

### Signals

```gdscript
signal setting_changed(category: String, key: String, value: Variant)
signal settings_committed
signal settings_cancelled
```

### Composable widgets

Drop any of these into your own scene and they wire to `OptionsManager` automatically:

| Scene | Type | Controls |
|---|---|---|
| `widgets/window_mode_picker.tscn` | OptionButton | Windowed / Fullscreen / Borderless |
| `widgets/resolution_picker.tscn` | OptionButton | Common resolutions up to screen native |
| `widgets/vsync_toggle.tscn` | CheckButton | VSync on/off |
| `widgets/fps_limit.tscn` | SpinBox | `@export min_fps`, `@export max_fps` |
| `widgets/bus_volume_slider.tscn` | HSlider | `@export bus_name` (any AudioServer bus) |

```gdscript
# Instance a volume slider for any audio bus:
var slider = preload("res://addons/netpunk.gametools/subsystems/options/widgets/bus_volume_slider.tscn").instantiate()
slider.bus_name = "Music"
add_child(slider)

# FPS limit spinbox with a custom range:
var fps = preload("res://addons/netpunk.gametools/subsystems/options/widgets/fps_limit.tscn").instantiate()
fps.min_fps = 30
fps.max_fps = 144
add_child(fps)
```

Widgets sync bidirectionally — a `cancel()` call updates all connected widgets automatically via `OptionsManager.setting_changed`.

## Loading Screen

`LoadingManager` is registered as an autoload. Call it from anywhere to trigger a scene transition with a loading screen overlay.

```gdscript
LoadingManager.go_to("res://scenes/level_2.tscn")
```

The loading screen (`loading_screen.tscn`) is a `CanvasLayer` (layer 128) placed directly under `/root`, so it survives the scene transition and disappears when the new scene is ready. `go_to()` returns immediately — no blocking or signals needed.

### Background images

Background images are configured in the **GameTools** editor dock under **Loading Screen**. Set the **Meta key** (e.g. `"chapter"`) and add **Background Mappings** — each row maps a metadata value to an image path. Set a **Default image** as the fallback when no save exists or no key matches.

At runtime the loading screen reads `SaveManager.get_last_slot_meta()[meta_key]`, looks the value up in your mappings, and falls back to the default.

**Per-call override** — pass a texture as the second argument to use a specific background for one transition, regardless of save state:

```gdscript
LoadingManager.go_to("res://scenes/dungeon.tscn", preload("res://ui/dungeon_bg.png"))
```

### Transitions

Select a transition type in the **GameTools** dock under **Transition**. The transition-in and resource load run concurrently — the scene is ready the moment the animation finishes.

| Type | Effect |
|---|---|
| `none` | Instant cut (default). |
| `fade` | Fades the loading screen in and out via alpha. |
| `slide` | Slides the loading screen in from an edge (configure **Direction**). |
| `shader` | Drives a custom `.gdshader` with `progress` and `invert` uniforms (see below). |

**Override at runtime** — set `LoadingManager.transition` to any `LoadingTransition` instance to bypass the dock setting:

```gdscript
var t := FadeTransition.new()
t.duration_in = 0.6
t.duration_out = 0.3
LoadingManager.transition = t
```

### Custom transitions

Subclass `LoadingTransition` and override `do_transition_in` and/or `do_transition_out`. Both are coroutines — use `await` freely to animate, play sounds, etc. The `LoadingManager` waits until each method returns before advancing.

```gdscript
class_name MyWipeTransition
extends LoadingTransition

func do_transition_in(screen: CanvasLayer) -> void:
    var tween := screen.create_tween()
    tween.tween_property(screen, "modulate:a", 1.0, 0.5)
    await tween.finished

func do_transition_out(screen: CanvasLayer) -> void:
    var tween := screen.create_tween()
    tween.tween_property(screen, "modulate:a", 0.0, 0.3)
    await tween.finished
```

**Shader transitions** — use `ShaderTransition` with any `canvas_item` shader. Your shader receives two uniforms:

- `uniform float progress : hint_range(0.0, 1.0)` — runs 0 → 1 for both in and out
- `uniform bool invert` — `false` during transition-in, `true` during transition-out

A sample shader is included at `subsystems/loading/transitions/shaders/fade_black.gdshader`. Copy it as a starting point:

```glsl
shader_type canvas_item;
uniform float progress : hint_range(0.0, 1.0) = 0.0;
uniform bool invert = false;

void fragment() {
    float p = invert ? 1.0 - progress : progress;
    COLOR = vec4(0.0, 0.0, 0.0, 1.0 - p);
}
```

Point the dock's **Shader** field at your `.gdshader` file, or assign it in code:

```gdscript
var t := ShaderTransition.new()
t.shader = preload("res://fx/dissolve.gdshader")
t.duration_in = 0.8
LoadingManager.transition = t
```

### Custom loading screen

Override the scene path before any transition to use your own themed scene. Your scene must expose a `set_progress(value: float)` method; optionally expose `set_background(texture: Texture2D)` to support per-call overrides.

```gdscript
LoadingManager.loading_screen_scene_path = "res://ui/my_loading_screen.tscn"
```

## Mod Support

`ModManager` is registered as an autoload and runs before `OptionsManager` and `LoadingManager`, so mods can override scenes and assets used by those systems.

### Mod format

Each mod is a Godot `.pck` file paired with a sidecar `.json` manifest of the same name:

```
user://mods/
  cool_mod.pck
  cool_mod.json
  other_mod.pck
  other_mod.json
```

The manifest is read **before** the PCK is mounted, so `ModManager` can show mod info and honour enable/disable state without committing to any PCK. The manifest file is optional — PCKs without one are still loaded, using the filename as the mod ID.

**`cool_mod.json`**

```json
{
  "id": "cool_mod",
  "name": "Cool Mod",
  "version": "1.0.0",
  "author": "Modder Name",
  "description": "Adds cool stuff.",
  "dependencies": ["other_mod"],
  "load_order": 0
}
```

All fields except `id` are optional.

> **Note:** Godot cannot unload a PCK once it is mounted. Calling `disable_mod()` saves the new state to disk, but the change takes effect only after the next game restart.

### API

```gdscript
# All discovered mods (including disabled ones), keyed by mod id.
ModManager.mods  # Dictionary[String, ModInfo]

# Mods that were successfully mounted this session.
ModManager.get_loaded_mods()  # Array[ModInfo]

# Enable / disable (persisted via SaveManager; effective next restart).
ModManager.enable_mod("cool_mod")
ModManager.disable_mod("cool_mod")

# Signals
ModManager.mod_loaded.connect(func(mod_id): print("loaded: ", mod_id))
ModManager.mod_load_failed.connect(func(mod_id, error): push_error(error))
ModManager.all_mods_loaded.connect(_on_mods_ready)
```

### ModInfo fields

| Field | Type | Description |
|---|---|---|
| `id` | `String` | Unique identifier (filename if no manifest). |
| `name` | `String` | Display name. |
| `version` | `String` | Semver string. |
| `author` | `String` | Author name. |
| `description` | `String` | Short description. |
| `dependencies` | `Array` | IDs of mods that must load first. |
| `load_order` | `int` | Lower values load first. |
| `source_path` | `String` | Absolute path to the `.pck` file. |
| `enabled` | `bool` | Whether this mod is enabled (persisted). |
| `is_loaded` | `bool` | Whether the PCK was mounted this session. |

### Steam Workshop

For Steam Workshop, obtain the item's install directory from GodotSteam and pass it to `scan_path()`. Call this before your game scene loads so mods are available immediately:

```gdscript
func _ready() -> void:
    # Query GodotSteam for each subscribed workshop item's install path.
    for item_id in Steam.get_subscribed_items():
        var info := Steam.get_item_install_info(item_id)
        if info.ret:
            ModManager.scan_path(info.folder)
```

`scan_path()` discovers and mounts all eligible mods in that directory immediately, then emits `all_mods_loaded` again.

### Steam DLC (depot-based)

DLC distributed as a depot alongside your game ends up in the game's install directory. Load the PCK directly — no scan needed:

```gdscript
func _ready() -> void:
    if Steam.is_DLC_installed(MY_DLC_APP_ID):
        ProjectSettings.load_resource_pack("res://dlc/my_dlc.pck")
```

### Configuring the mods directory

The default scan path (`user://mods/`) can be changed in the **GameTools** dock under **Mods**, or overridden in code before the autoload's `_ready()` fires:

```gdscript
# In Project Settings → gametools/mods/mods_path
# or directly:
ProjectSettings.set_setting("gametools/mods/mods_path", "user://my_game/mods/")
```

## Start Menu

Instance `start_menu.tscn` as your game's opening scene. It exposes four signals and hides the **Continue** button automatically when no saves exist.

```gdscript
var menu := preload("res://addons/netpunk.gametools/subsystems/start_menu/start_menu.tscn").instantiate()
add_child(menu)

menu.new_game_requested.connect(_on_new_game)
menu.continue_requested.connect(_on_continue)    # carries last-used slot_index: int
menu.load_game_requested.connect(_on_load_game)  # show your slot-picker UI here
menu.quit_requested.connect(get_tree().quit)

func _on_new_game():
    LoadingManager.go_to("res://scenes/new_game.tscn")

func _on_continue(slot_index: int):
    var save := SaveManager.load_slot(slot_index)
    # restore game state from save.data / save.meta as needed
    LoadingManager.go_to("res://scenes/game.tscn")

func _on_load_game():
    # show your custom slot-picker scene
    # when the player selects a slot:
    var save := SaveManager.load_slot(chosen_slot)
    LoadingManager.go_to("res://scenes/game.tscn")
```

### Background image from save metadata

The start menu uses the same meta key and background mappings configured in the **GameTools** dock under **Loading Screen**. It reads `SaveManager.get_last_slot_meta()[meta_key]` and falls back to the default image when no save exists or the key doesn't match.

## Setting Builder

The Setting Builder is an **editor-only tool** for defining your game's custom settings hierarchy. It lives as a scene you drop into your project during development and lets you declare setting groups (sliders, checkboxes, color pickers, option buttons) without writing boilerplate.

### Workflow

1. Add `setting_builder.tscn` to any scene in your project.
2. Add `SettingsTabBar` children to represent categories (Video, Audio, Gameplay, etc.).
3. Inside each tab, add `SettingsGroup` nodes, then `SettingValue` nodes for individual settings.
4. On each `SettingValue`, choose the widget type and configure its properties in the Inspector.
5. Call `export_settings()` to get the full configuration as a nested dictionary.

```gdscript
var config = $SettingBuilder.export_settings()
# Returns a nested structure:
# [
#   "SettingBuilder",
#   {
#     "Gameplay": {
#       "Combat": {
#         "difficulty": { "type": "OPTION_BUTTON", "options": ["Easy", "Normal", "Hard"] },
#       }
#     },
#     "Accessibility": {
#       "Text": {
#         "text_scale": { "type": "SLIDER", "min": 0.5, "max": 2.0, "step": 0.1, "value": 1.0 },
#       }
#     }
#   }
# ]
```

### Available widget types

| Type | Exported keys |
|---|---|
| `CHECKBOX` | `type`, `selected` |
| `CHECK_BUTTON` | `type`, `selected` |
| `SLIDER` | `type`, `min`, `max`, `step`, `value` |
| `SPIN_BOX` | `type`, `min`, `max`, `step`, `value` |
| `OPTION_BUTTON` | `type`, `options: [String, ...]` |
| `COLOR_PICKER` | `type`, `color` (hex string) |

The Setting Builder is not intended for runtime use — export the config during development, then use the resulting dictionary to drive your in-game options UI and `OptionsManager.set_setting()` calls.
